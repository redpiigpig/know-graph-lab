# 會議論文集排版 Pipeline

把 N 位作者、體例完全不一致的來稿，排成一本可付印的會議論文集。

> 🚨 **截圖規則 — 絕對禁止 >2000px**：任一邊超過 2000px 會炸掉整個 session。要看海報／樣稿先用 PIL 縮到 ≤1600px 再讀。

---

## §A 為什麼不要用 Word 手排

15 篇稿、每篇體例不同、作者還會中途送修訂版、議程還會改版。手排的話每次改動都要重做一遍。
本 pipeline 做成**可重跑**的：換一篇稿只要改 `papers.py` 一行再跑一次，頁碼、目錄、頁首全部自動重算。

---

## §B 資料源盤點（開工第一件事）

排版前先把這些東西找齊，缺哪個要當場問：

| 東西 | 通常在哪 | 作用 |
|---|---|---|
| 各篇來稿 | 承辦分享的 Drive 資料夾 | 正文 |
| **大會議程**（最新版！） | Drive 或使用者本機 Downloads | **編號與排序的唯一依據** |
| 排版樣稿（含版式的單篇範例） | 使用者桌面 | 量出所有版式參數 |
| 上一屆論文集 PDF | 使用者桌面 | 體例參照（頁碼位置、前置頁有哪些） |
| 學者資料庫 xlsx | 本機 Downloads | 與會學者名錄的單位／職銜 |
| 工作人員清單 | Drive（Google Doc） | 全書最後一頁 |
| 大會海報 | 本機 Downloads | 指導／主辦／協辦／承辦單位 |

**Google Doc 要下載成 docx**：`https://docs.google.com/document/d/{id}/export?format=docx`
**Drive 一般檔**：`https://drive.google.com/uc?export=download&id={id}`

## §C 二十一條血淚教訓（每一條都真的踩過）

### 1. 議程是唯一權威；Drive 檔名經常是舊的
第三屆的例子：議程場次四之二是「寧瑪 → 薩迦 → 格魯」，但 Drive 上薩迦仍叫 `4.2.1`、
寧瑪叫 `4.2.2`。使用者明確說過「**Drive 上的檔名是舊的**」。
→ **一律照議程排序編號**，Drive 檔名只當找檔用。發現不一致就在清單裡列出來請承辦改。

### 2. 一律以「論文本身」的題名與署名為準
議程題名常是投稿時的舊題（第三屆有 7 篇不符）。作者名也可能三種寫法：
資料庫「阿旺赤列」／議程「昂望聽列執行長」／論文署名「昂望聽列」。
→ 題名、署名取論文；**職銜等會異動的資訊取議程**（議程比資料庫新）。
→ 但**不要**拿議程的泛稱敬稱（一律「教授」）去蓋掉資料庫的精確職級（助理教授／兼任副教授）——
   那是降低準確度，不是更新。這點要主動說明並讓使用者決定。

### 3. 個資絕對不印
學者資料庫裡有手機、聯絡電話、email、通訊地址。論文集是要發出去的印刷品。
→ 名錄**只取**姓名／所屬單位／職銜／角色／場次。這件事要主動講，不要等使用者發現。

### 4. 樣稿指定的字型可能根本沒人有
第三屆樣稿指定文鼎粗明／全真特明體／全真粗圓體／全真中黑體 —— 這台電腦沒有，
而且**樣稿 PDF 自己內嵌的字型清單裡也沒有**（做樣稿那台也沒裝，Word 早已代換）。
→ 用 PyMuPDF `get_page_fonts()` 驗樣稿 PDF 實際內嵌了什麼。
→ 決策：**照樣稿原樣保留字型名稱**（規格一致、輸出結果與樣稿相同），但要告知使用者，
   讓他決定是買字型還是改規格。

### 5. 頁碼位置照上一屆，不要照樣稿
樣稿（單篇）把頁碼放頁首；上一屆論文集（成書）放**頁尾正中**。成書體例以上一屆為準。
用 PyMuPDF 讀上一屆 PDF 的 block 座標可以直接驗證（y≈786/842 → 頁尾；x 居中）。

### 6. 本文頁碼獨立起編 → 目錄兩趟回填才穩
前置頁（書名頁／目錄／議程／名錄）**不編碼**，本文從 1 起連續編。
這樣目錄裡的頁碼不受前置頁長度影響，於是可以：
第一趟組裝拿頁碼 → 生成真目錄 → 第二趟組裝。目錄頁數變化不會使頁碼失準。

### 7. 每篇一節、奇數頁起排
`wdSectionBreakOddPage`。每篇獨立一節才能各自掛自己的書眉。會產生空白背頁，那是正常的。

### 8. 直接格式覆寫，不要動 styles.xml
逐篇重排的做法是**在來稿上就地覆寫 pPr/rPr**（直接格式勝過樣式），
這樣註腳、圖片、表格、藏文、清單編號全部原樣保留。不要試圖換 styles.xml（style id 對不上）。

### 9. 段落層級的 sectPr 一定要清乾淨
來稿內含分節符（橫向頁等）→ 合本後多出節 → **頁首套到錯的節上**。
第三屆曾因此多出 4 節，關婉玲那篇的書眉跑到別人頭上。
→ `for s in root.iter(Q("sectPr")): s.getparent().remove(s)`，然後只補一個自己的。
→ 驗收：`build/` 每個檔應該**剛好 1 個 sectPr**，合本後節數 = 檔數。

### 10. 來稿拿空段落當行距 → 版式套上去就是滿篇空行
第三屆哈欣仁波切那篇有 194 個空段落（作者用 Enter 拉行距）。版式本身已有固定行高，
空段落原樣保留就變成滿篇空洞，26 頁裡有 6 頁是空的。
→ `papers.py` 該篇加 `squeeze=True`，`build.py` 的 `drop_blank_paras()` 全部清掉。
→ 但**表格內的空儲存格段落要留**，**兩個表格之間的空段也要留**（拿掉 Word 會把兩個表合成一個）。

### 11. 表格會被拆到兩頁：項目欄留在前頁、內容欄跑到次頁
`build.py` 的 `keep_tables_whole()`：每列補 `w:cantSplit`，末列以外的段落補 `w:keepNext`，
**表格正上方那一段小標也要 keepNext**，否則標題留在前頁、表身整塊跳頁。
驗收用 PyMuPDF `page.find_tables()` 逐頁列出表格 bbox，同一個表不該出現在相鄰兩頁。

### 12. 頁碼字型要等功能變數插完再設
`rng.Font.Name = "Times New Roman"` 設在 `Fields.Add(wdFieldPage)` **之前**沒有用——
Word 插入功能變數後會把字型套回樣式，實測印出來是 Calibri。
→ 插完 `Fields.Update()` 之後，對 `fld.Result` 與 `hf.Range` 各壓一次 `Font.Name`。
→ **不要**在含功能變數的範圍設 `NameFarEast`，會炸 `OLE 0x800a16d4` 讓整個合本中斷
   （頁首沒有功能變數，設 NameFarEast 沒問題）。
→ 驗收：PyMuPDF 讀頁尾 span 的 `font`，不要只看有沒有報錯。

### 13. 篇首頁不要再印一次會議名
排版樣稿是單篇抽印本，篇首會印大會名稱；但合本後書眉已經單雙輪流
（單數頁篇名／雙數頁會議名），篇首頁再印一行就變成「兩個頁首」，
而且那行是內文段落、字型與書眉不同，看起來更亂。
→ `title_block()` 不加 `conf` 那一段。既有的 `單篇排版檔` 就地用 lxml 刪掉那一段即可。

### 14. 參考文獻換頁：判斷式不能只認完全相符，也不能改成「包含」
實際遇到的寫法有「參考文獻 (References)」「參考文獻與網站資料」「參考書目」。
完全相符抓不到前兩種；但改成「包含參考」又會誤抓哈欣那篇內文的
「配合參考資料：」（課程教材的行內標籤，共 6 處）而把它們各自換一頁。
→ `is_ref_heading()`：**開頭相符 ＋ 長度 ≤ 20 字**。
→ 換頁用 `w:pageBreakBefore`，注意 `w:pPr` 子元素有固定順序
   （pStyle→keepNext→keepLines→pageBreakBefore→…→spacing→ind），插錯位置 Word 當壞檔。

### 15. 節間空一行要「補到恰好一個」，不是無腦插
各篇原稿本來就有沒有空行不一致：squeeze 過的那篇一個都沒有，別篇每節前本來就有。
→ 規則寫成「節標題前若不是空段落才補一個」，跑幾次結果都一樣。
→ 摘要／Abstract 緊接在署名之下，不算節，不補。

### 16. TaskStop 掉跑到一半的 assemble，會留下隱形 Word 卡住後續所有 COM 呼叫
症狀：下一次跑 `doc.Range(...)` 直接回 `接收者已拒絕這個呼叫`（RPC_E_CALL_REJECTED）。
`Get-Process WINWORD` 會看到一個 **MainWindowTitle 空白**的實例，
`GetActiveObject` 接得上但 `Documents.Count` 有一堆插到一半的文件、再問就被拒。
→ 那是自己留下的孤兒（Visible=False），確認標題空白後直接 Stop-Process，再重跑。
   使用者自己開的 Word 會有視窗標題，別誤殺。

### 17. 改標題文字：一定要走 `w:t` 後代，而且改完要重讀驗證
`p.findall(Q("r"))` 只拿得到**直屬**的 run。Google Docs 匯出的稿子 run 被包了一層
（`w:sdt`、`w:hyperlink`…），於是改字的函式什麼也沒改、卻照樣回報成功——
第三屆 1.1 那篇因此連跑兩次都沒生效，直到把 PDF 抓出來比對才發現。
→ 一律 `for t in p.iter(Q("t"))`：第一個塞新字，其餘清空。
→ **驗收看重讀後的檔案內容，不要看腳本自己印什麼。**批次改完加一段 re-open 檢查。

### 18. 標題編號的頓號：篇內不一致才是漏字，全篇一致是體例
第三屆的分法：專題演講第一～三章有「、」、第四～六章沒有 → 漏字，直接補；
1.1 六個節、3.1 六個章全都沒有 → 作者體例，**先問過**再統一（大會後來決定補）。
順帶會看到的其他標題問題：編號後多半形空格、摘要標題多冒號、
兩個標題被轉檔併成一行（拆成大標＋小標）、有節無「第一節」（前言未編號）。

### 19. 空白與換行體檢：用 `wsaudit.py` 掃，逐條判斷，不要整批清
`wsaudit.py` 掃全書的段首空白、中文間空格、硬換行、連續空格、段尾空白、tab。
掃出來的每一類都要分「轉檔殘跡」與「作者刻意」：

| 現象 | 該清 | 不該清 |
|---|---|---|
| 段首空白 | 手打的 7–9 個空格（首行縮排是版式給的） | — |
| 中文間空格 | 斷行殘跡（「為假 時」） | **標籤與正文之間的空隔**（劉宇光那篇每段都是）、署名與單位之間 |
| 硬換行 w:br | 段首段尾多出來的、連續兩個以上（＝作者拿 Shift+Enter 當分段） | 偈頌分句、圖說分行、篇名與副題 |
| tab | 段首的 | 清單編號後的 |
| 全形空格 | — | 表號後（「表二　…」） |

→ **清完一定要 diff 文字對照 `build_bak/`，逐條看過**。第三屆這樣抓到兩處誤傷。
→ 連續兩個以上 w:br 要真的拆成段落（`brfix.py`），拆的時候保留原 run 與字型，
   不要抽純文字重建——藏文、拉丁字、註腳參照都在 run 裡。
   `w:proofErr`／`w:bookmarkStart`／`w:bookmarkEnd` 略過即可；遇到 `w:hyperlink`／`w:sdt` 就別拆那段。

### 20. 整篇粗體：會同時被當成「字體不一樣」與「太黑」
第三屆 4.3.1 原稿 97% 的 run 是粗體（其他各篇 1–15%）。
樣稿指定的字型本機沒有 → Word 代換成新細明體 → 新細明體**沒有粗體字面**，
只能合成假粗體，於是筆畫變粗、字形也走樣，讀者看到的是「這篇字體跟別人不同」。
→ 交件前用 PDF 逐篇統計字型與粗體比例，離群的那篇清掉 run 與段落標記的 `w:b`／`w:bCs`。

### 21. Google Docs 匯出的三種殘留
- **`w:sdt` 包住 run**：python-docx 的 `.text` 讀不到 → 一律用 lxml 走原生 XML。
- **頁碼變成內文段落**（「第 N 頁」×32）→ 用 `strip` regex 濾掉；**濾掉後要把被它切斷的句子接回**。
- **中文字之間的斷行空格**（「梳 理其教育體制」×300 餘處）→ `despace()`。

## §D 分類器的幾個坑

| 坑 | 症狀 | 解法 |
|---|---|---|
| 書目被判成標題 | 「1.《青史》，四川民族出版社，1984 年，第 70 頁」變 14pt 粗體標題 | `LISTY` 守衛：含《》／頁／年／http 的不算標題 |
| 整份文件都粗體 | 打散的課程表每行都變標題 | 統計整段粗體比例，>12% 就**不拿粗體當標題訊號**，內文也不沿用原稿粗體 |
| 標題層級亂 | 第X章 和 一、 混在一起 | **先出現的編號體系＝第一層**，其餘降第二層（`scheme_of()`） |
| 無編號小標漏抓 | 盧佳慧那篇小標是純文字粗體 | 短（≤40 字）＋整段粗體＋不以標點結尾 → 標題（受上面的比例守衛節制） |
| 圖說被套內文版式 | 文字方塊內文字級數被改掉 | 祖先含 `txbxContent/drawing/pict/object` 的段落**跳過** |

## §E 環境地雷

- **Bash heredoc 會弄壞中文**：寫含中文的 .py 或中文檔名一律用 **Write 工具**或 Python，
  不要用 `cat > f <<'EOF'`（實測把「教育」寫成「教灶」、「噶舉」寫成「噶縫」，
  且長內容會讓 bash 直接 parse error）。所有 Python 執行加 `PYTHONUTF8=1`。
- **Word COM 用 late binding**：`win32.Dispatch("Word.Application")`。
  `gencache.EnsureDispatch` 會炸 `CLSIDToClassMap`。常數自己寫死。
- **不要無條件 `app.Quit()`**：會關掉使用者自己開著的 Word 文件。
  改成 `if app.Documents.Count == 0: app.Quit()`。
- **中斷組裝會留下同名文件開著** → 下次 `SaveAs2` 被 Word 擋（"無法給一個與開啟文件相同的檔案名稱"）。
  開頭先掃 `app.Documents` 關掉同路徑的。
- **`build.py` 只清自己的檔**（`^\d{2}_`），別把 `front.py` 產的前置頁一起刪了。
- 組裝兩趟＋PDF 約 10 分鐘 → 用 `run_in_background`。改東西時先 `TaskStop` 舊的，
  兩個 Word 同時寫同一個輸出檔會打架。

## §F 檔案與執行順序

`scripts/` 內：

| 檔 | 作用 |
|---|---|
| `ttbf.py` | 版式核心：字型常數、`ROLE` 版式表、段落分類器、`restyle_para()` |
| `papers.py` | **篇目表**——順序、編號、來源檔、起始標記、題名／副題／署名。改稿改這裡。<br>選用欄位：`squeeze=True` 清空段落、`toc_num` 只改目錄顯示的編號（內部編號與檔名不動） |
| `build.py` | 逐篇重排 → `build/NN_編號.docx`（含 despace／merge_back／註腳部件注入） |
| `front.py` | 前置頁：書名頁、目錄、議程、與會學者名錄（表格）、工作人員名單 |
| `assemble.py` | Word COM 合本：分節、版面、頁首書眉、頁尾置中頁碼、兩趟目錄回填 |
| `topdf.py` | 匯出 PDF |
| `dump.py` / `spec.py` / `audit.py` / `inv.py` | 診斷：抽文字／抽版式參數／驗分類結果／盤點來稿要件 |
| `wsaudit.py` | 空白與換行體檢（唯讀）：段首空白／中文間空格／硬換行／段尾空白／tab |
| `brfix.py` | 段首段尾多餘的 w:br 拿掉；連續兩個以上 w:br 拆成真正的段落 |

執行順序（**front 一定要在 build 之後、assemble 之前**）：

```bash
PYTHONUTF8=1 python build.py     # 逐篇重排
PYTHONUTF8=1 python front.py     # 前置頁
PYTHONUTF8=1 python assemble.py  # 合本（內含兩趟）
PYTHONUTF8=1 python topdf.py     # 出 PDF
```

抽換單篇：改 `papers.py` 的 `src` → 重跑全部四步。
**只重排某幾篇**：`python build.py 4.2.3`（給編號就只動那幾篇，其餘沿用既有 `build/`，
也不會清掉別人的檔）。原稿早就不在本機、只剩 `單篇排版檔/` 時，這是唯一能改的路——
單篇的小改（例如換個署名）就直接對 `build/NN_x.docx` 動 lxml，再跑 front＋assemble。

## §G 版式規格（第三屆實例，換屆要重新量）

## §H 全書結構

```
書名頁（指導／主辦／協辦／承辦單位依海報）
目錄（點狀前導、頁碼右對齊、自動回填）
議程表（大會原檔套版式；標題區置中）
與會學者名錄（四欄表格：姓名／所屬單位／職銜／角色（場次））
── 本文（每篇一節，奇數頁起，頁碼從 1 連續）
附錄（例：同一篇的英文版）
工作人員名單
```

**名錄與工作人員名單的書寫慣例**：僧職稱謂併入姓名欄——法師綴於名後、**堪布冠於名前**
（堪布其美多吉、堪布澤仁扎西），**不寫「釋」**（釋昭慧法師→昭慧法師、釋如王→如王法師）；
姓名已含該稱謂時，職銜欄裡重複的一份要去掉。
但**工作人員名單依大會原檔**，不套這條體例（第三屆承辦定稿寫「釋融德」就照印）。
本屆決定**不收發表人簡歷與照片**，簡介統一集中在名錄，不放每篇之前（上一屆是每篇前一頁簡歷）。

## §I 交件

放使用者桌面 `第三屆藏傳佛教論壇論文集/`（換屆改名），內含：

- `<會議名>會議論文集.docx`（可編輯）
- `<會議名>會議論文集.pdf`
- `稿件檢查與缺件清單.md` ← **要寫這份**，承辦拿去催稿
- `單篇排版檔/`（每篇獨立 docx，抽換用）

成果另存 Drive「知識圖工作室」對應區。

**缺件清單要寫什麼**：整篇缺稿／論文要件現況（摘要‧關鍵詞‧參考文獻）／題名與議程不符對照表／
姓名與職銜不一致／編號對照（Drive 舊檔名 vs 論文集編號）／重複與同內容不同格式的檔／
字型狀況／前置頁待補項。**不要**把「缺關鍵詞、缺參考文獻」當待辦硬催——
第三屆的決定是「沒有的就照收」，清單裡改成存查用。

## §J 交接慣例

- 每次改動後**抽頁複檢**（PyMuPDF 轉圖用 Read 看），不要只看不報錯就交件。
- 頁數變動要主動列出前後對照表（哪幾篇頁碼往後移）。
- 發現來源檔本身的問題（表格被打散成純文字、兩個標題併一行）→ **照原樣排，不代作者重建結構**，
  但要寫進清單請作者修原檔。
