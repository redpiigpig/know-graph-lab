### 舊構想的子目怎麼歸（2026-09-06 定）

2021 那份的八部子目比現行細。**「救／度」的張力 2021 就已經是子目**（拯救論／解脫論）
——二元張力設計不是 2025 才發明的。孤兒子目的歸法：

- **障礙論**（罪／無明／業障／我執）→ 卷五救度論**卷首**（要從什麼裡被救出來）
- **儀軌論** → 卷六教團論　**眾生論** → 卷二宇宙論
- **基本神學**（整體／歷史／個體思維）→ 不另立卷，化進總綱與卷一第一章
- 🚨 **卷四聖者論要照 2021 的「顯聖論」內涵寫**：神聖顯於人（先知／化身／聖者）、
  顯於物（聖物／聖像／舍利）、顯於言（靈感）。只寫人物會漏掉一半。卷名保留「聖者論」。

## 全書的方法（違反了就是寫壞了）

- **三原則**：多元化／科學化／人間化。
- **雙軸**：歷史先後為縱軸（各傳統在彼此壓力下演變），神學結論光譜為橫軸。
- 🚨 **對話性不是整合性**：使用者明講不要萬教合一——那只會多生一個宗教（摩尼教、巴哈伊
  都是紀錄在案的例子）。相似之處要指出來，但立刻要問「這個相似是真的相同，還是我們的
  分類太粗糙」。
- 🚨 **張力多在傳統內部，不在傳統之間**。「救／度」看似基督教對佛教，但淨土與禪爭的是
  同一條軸，奧古斯丁與貝拉基爭的也是。比較的單位是「同一條軸上各傳統的內部爭論落在
  哪些位置」，不是「甲教說 A、乙教說 B」。
  判準：**一組張力若不能在至少兩個傳統內部各找到一場真實的爭論，它就只是一對漂亮的字。**
- **兩個要避開的陷阱**：形上學霸權（預設諸教指向同一個終極實在）與人類學還原論
  （把宗教主張翻譯成心理或社會功能就算解決了）。

### 卷一《天人論》的主張與界線

**主張**（2026-09-06 使用者親自定調）：**每個傳統的神觀與它的人觀是同一個問題的兩面**，
互相定義、動一邊另一邊非動不可。寫成**可推翻的形式**：神觀重大移動時人觀必須同步移動，
找得到單邊移動的案例就得修改（失效案例反而指出連動的**傳導條件**——要靠儀式、教育、
制度才傳得過去）。🚨 **相關 ≠ 投射**，要跟費爾巴哈切開。
收束句：**人法天，天法理，理法道，道法人**（改老子那句成閉環）。

🚨 **卷與卷的界線**（使用者指出 Claude 排錯過一次）：**苦難與惡本身歸卷五救度論**；
天人論只留「神會不會受苦、會不會改變」這條神的**屬性**爭論。兩者常被混在「神義論」
名目下，但前者問終極實在的樣態，後者問人的出路。

## 🚨 這條線特有的「看起來成功的失敗」

寫這 84 章的過程踩過的坑，每一個都是**單看那一章毫無異狀**的那種。

### 一、捏造書目

叫模型寫註釋，它會生出格式完美、出版社與年份俱全、**但根本不存在**的條目。這種錯不報錯，
會一路安靜長到成書。**所以初稿階段一律禁止模型產生註釋與參考書目**，正文提到人名經典名
沒問題，但出版社、年份、頁碼、卷期一律禁止。註釋等定稿後照 [[works-research-review]]
那套「先策展再逐筆核實」另補。

### 二、重複退化（最陰險）

模型陷入迴圈，尾段變成同一個字反覆貼。D6:05 吐了 15,385 字，其中 13,809 字是連續的
「領」——**字數漂亮、前七項檢查全過**，只有結尾標籤沒閉合才露餡。不能靠那個露餡，
所以閘門第八項直接掃單字元連續與尾段迴圈。

### 三、檔案數對 ≠ 章數對

- **整章被複製兩份**（D5:01）。加厚那輪有時把原稿與加厚稿一起吐回來，而舊版 `clean()`
  取「第一個 `<section` 到最後一個 `</section>`」，剛好兩份都收下。組出來的卷會多一章，
  但**檔案數是對的**。
- **每個小節後面都補一個 `</section>`**（D6:06，七個）。瀏覽器會自己容錯，頁面完全正常。

`clean()` 現在只留第一個 section、中途的結尾標籤全拿掉最後補一個。**驗收要數組裝後的
章數，不要只數檔案。**

### 四、卷名幻覺與抄範例

不把七卷全名寫進 prompt，模型會自己發明（實測把卷一叫成《終極實在論》）。
餵文風範例會被照抄例子（卷二第一章原樣搬走卷一的台灣餐桌場景）——要明講只學語氣。

### 五、檢查規則本身要夠準

**粗糙的檢查比沒有檢查更糟，因為它會訓練人忽略警告。** 這條規則已經誤傷三次：
拿「終極實在論」當卷名幻覺關鍵詞，把「其終極實在論的宣稱」報成錯；
拿「地基主」當抄範例判準，把講鬼神那一章的恰當用例報進去；
拿「出版社」當書目關鍵詞，把「經營的醫院、學校、出版社」報進去。
現在：卷名只比對 `卷N《X》` 的實際卷名，抄範例要兩個以上標記同時出現，
「出版社」只在書名號緊鄰或後接年份時才算。**改判準要附自我測試。**

反方向的漏報也一樣要防：清贅詞的規則從「只認原形」一路補到「程度副詞前綴」再補到
「連接詞前綴」，打了三輪地鼠才改成一次涵蓋「句首＋短連接語」。

## 🚨 長跑的工程教訓

- **過夜工作只有 Windows 排程活得下來。** 背景程序隨 Claude session 結束被砍過三次。
  用 `run_dialogical_write.bat` ＋ 排程，腳本可重入（已存在的章直接跳過）。
- 🚨 **bat 裡的 python 要寫絕對路徑**。Task Scheduler 的 PATH 跟互動 shell 不一樣，
  寫 `python` 會找不到執行檔、任務回 `LastTaskResult=1` 而且**一個字都不寫 log**——
  看起來就像排程根本沒跑。為此空轉了一整天。
- **單一實例鎖**：排程每半小時醒來、一輪要跑好幾小時，沒鎖的話第二個實例會挑到同一批
  「還沒寫」的章，兩邊各寫各的白燒額度。用鎖檔 mtime 判活性（不查 PID）＋跑的過程心跳。
- 🚨 **任務結束就 Disable-ScheduledTask**。判準看產出（84 章到齊）不看排程狀態。
  本輪已 Disable。

### 引擎與長度

`ask_any()` 三層備援 **Gemini → NVIDIA → OpenRouter**，單章失敗只算那一章失敗、
絕不中斷整場。實測三者都會整片 429（2026-09-08 曾只剩 NVIDIA 活著）。

🚨 **平行時要輪流換 key**：`_openai_style` 原本每次都從 `keys[0]` 打起，四條線會全部
擠在同一把上，七把 key 只用得到一把。

🚨 **短稿不要丟掉重寫，送去加厚。** 一次成稿的長度看引擎：Gemini 多半六到八千字，
NVIDIA 常常只有三到五千。早期「不足六千判退重寫」的規則，在 NVIDIA 上讓 25 章敗了
17 章——重寫出來的還是短稿，而加厚這道有效手段（實測 4,000→9,000、7,060→11,682）
反而只對已經夠長的稿子開放。三個門檻分工：

| 門檻 | 值 | 作用 |
|---|---|---|
| `MIN_CHARS` | 2,500 | 低於此才算根本沒寫完、值得整章重來 |
| `EXPAND_BELOW` | 8,200 | 不到就送加厚，最多兩輪 |
| `MIN_KEEP` | 6,000 | 加厚兩輪後仍不到才算失敗 |
