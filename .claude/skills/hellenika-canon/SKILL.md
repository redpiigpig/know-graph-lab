## 1. 編纂立場（本藏經自己的三條，不是別人的）

**一、這是一部外加的正典，編者自陳。**
希臘宗教沒有正典、沒有經書、沒有教義會議，這正是它輸給基督教的原因之一。本藏經替它補做這件事——但**不冒充古人的自我認定**。廿四卷的分法是編者按聖經文類光譜所立，不是任何古代希臘人會承認的分類。凡例第一句就要講明這件事，不能讓讀者以為古人自己這樣分。

**二、不調和。**
多神信仰本來就容納互斥版本。神譜有赫西俄德、俄耳甫斯、費瑞居德、斯多噶寓意四套，彼此矛盾；塞拉皮雍神廟被毀有異教方與基督教方兩份記述，差距極大。**一律並置，不取捨、不折衷、不編一個「綜合版」。** 這是體例而非權宜——它正是本藏經勝過任何一本「希臘神話故事集」的地方。

**三、殘缺是內容的一部分。**
全書 250 種裡，完整傳世不到三分之一（殘篇 89、銘文紙草 40、敵證 9）。存世狀態不是元資料，是這些文本的**處境本身**：一個靠敵人保存下來的宗教，其正典必須把敵人也放進來。所以四級狀態一律在版面上標色標明，並記 `via` 轉引來源（§5）。

## 3. 編次原則：兩個時鐘

這是本藏經最容易被改壞的地方，任何重排前務必回讀。

**前十四卷（Α–Ξ）＝ 文本權威位階與成書早晚，不按所敘事件先後。**
根據是希羅多德 2.53：「是荷馬與赫西俄德替希臘人造了神譜，給諸神定了名號、職司與形貌。」所以荷馬兩部史詩排在第三、四卷（Γ 大戰記、Δ 歸返記），緊接神譜與人類世代記之後，**而不是**等到列祖、英雄之後才出現。
> 反例警示：若按內敘時間排，公元二世紀的阿波羅多洛斯《書庫》（講創世）會被排到荷馬前面。那顛倒了希臘人實際的宗教生活——每個希臘人都讀荷馬，沒有人讀阿波羅多洛斯。**這個錯誤 user 明確否決過一次，不要再犯。**

**後十卷（Ο–Ω）＝ 成書年代，卷內亦由早到晚。**
時間軸在 Ο 卷開頭回捲到公元前 700 年。**回捲不是瑕疵，是正典體例**——列王紀寫到被擄，詩篇又回到大衛。

**卷內按年代排會長出敘事，這是設計而非副作用**：
- Ο 詩頌集：荷馬詩頌（前 7c）→ 品達 → 卡利馬科斯 → 俄耳甫斯詩頌 → 尤利安 → 普羅克洛七頌（5c，神廟已閉、禱詞只求「引我的魂脫離幽暗」）。一千兩百年的祈禱語言變化本身就是論證。
- Ψ 爭辯書：塞爾蘇斯 178（我來揭穿你們）→ 波菲利 → 希耶羅克勒斯 → 尤利安 362 → 利巴尼烏斯 386（請留我們一座神廟）。節節敗退，不必評論。
- Τ 神諭書：止於普魯塔克《論神諭的衰微》。最後一則神諭刻意留給 Ω 卷開篇。

**新增條目時**：前十四卷插入位置看該文本的權威與成書早晚；後十卷插入位置看成書年代。兩者都不看它「講的是什麼時代的事」。所敘年代填 `era_narrated` 欄，站上另有讀序可切。

## 4. 歸卷準則：按宗教系統，不按語言也不按作者

**唯一準則**：這份材料屬於哪一套宗教？

| 條目 | 語言 | 歸卷 | 為什麼 |
|---|---|---|---|
| 普魯塔克《努瑪傳》《羅慕路斯傳》 | 希臘文 | **羅馬卷 I／II** | 講的是羅馬祭儀與王政 |
| 西塞羅《論神性》 | 拉丁文 | **希臘卷 Φ** | 轉述的是斯多噶與伊比鳩魯的希臘學派神學 |
| 西塞羅《論卜筮》 | 拉丁文 | **羅馬卷 IV** | 講的是羅馬鳥卜與內臟卜 |
| 奧維德《變形記》 | 拉丁文 | **希臘卷 Α／Β／Ζ**（續典欄） | 希臘神話的拉丁重述 |
| 奧維德《歲時記》 | 拉丁文 | **羅馬卷 III** | 羅馬節期逐日釋義 |
| 帝王崇拜銘文（希臘城邦刻） | 希臘文 | **希臘卷 Κ** | 執行者是希臘人、儀節是希臘的，屬希臘祭儀晚期形態 |

> 同一位作者兩邊都有是常態，不是錯誤。西塞羅與奧維德各自被切成兩半，正好示範分界線在哪。

**「羅馬時代」≠「羅馬的」。** 普魯塔克、保薩尼亞斯、阿里斯提德斯、斐洛斯特拉托斯、普羅提諾、揚布利科斯活在羅馬帝國治下，但用希臘文寫作、事奉希臘諸神——他們是希臘卷主體，不要因為年代晚就往羅馬卷丟。

**羅馬卷為何另立而非打散**：羅馬宗教的核心是神事法（ius divinum）而非神學，是祭司團、曆法與卜筮而非神譜與救贖。文類分佈跟希臘那套對不上，硬打散會把廿四卷的骨架撐壞。

## 5. 資料 schema · `data/hellenika/types.ts`

```
HellenCanon  ├ parts: HellenPart[]      # 部，只放 volume key，供索引頁分組
             └ volumes: HellenVolume[]  # 卷
HellenVolume ├ sigil  Α / Ω / I / VI    # 顯示用卷次符號
             ├ parallel                # 聖經對位，如「創世記 3–9」
             ├ clock  mythic|historical # 兩個時鐘，見 §3
             ├ span                    # 「700 BCE–450 CE」
             └ divisions: HellenDivision[]
HellenWork   ├ title_zh / title_orig / author / era / place / language / extent
             ├ era_narrated            # 所敘年代（神話內敘時間），供第二讀序
             ├ parent                  # 母合集，如「史詩循環」「希臘魔法紙草」
             ├ note                    # 一行，顯示於標題下
             ├ intro                   # 100–200 字，見 [[hellenika-curate]]
             ├ status                  # 四級，見下
             ├ track  main|latin       # latin = 續典，版面加「續」標
             ├ via                     # 殘篇／敵證的轉引來源，必填
             ├ seealso                 # 跨藏經互見
             └ link                    # 站內對照工具
```

### 四級存世狀態（`status`）

| 值 | 顯示 | 何時用 | 必要配套 |
|---|---|---|---|
| `whole` | 全本（綠） | 完整傳世 | — |
| `fragment` | 殘篇（琥珀） | 原書已佚，靠引文／摘要／紙草綴輯 | **必填 `via`**；`extent` 記原書規模（「原 15 卷」） |
| `inscription` | 銘文／紙草（藍） | 石刻、鉛片、金葉、紙草等儀式現場文本 | **必填 `place`**；`extent` 記數量（「現存逾 4,000 片」） |
| `hostile` | 敵證（玫瑰） | 僅存於基督教作家為駁斥而作的引用 | **必填 `via`**；`intro` 須警告框架受敵手支配 |

> `status` 不填＝`whole`。**不要為了版面好看而漏標**——漏標會讓《婦女名錄》殘篇看起來跟《伊利亞特》地位相當，那是本藏經最不能犯的錯。

### 續典（`track: 'latin'`）收錄準則

拉丁文獻不另設專區，嵌進對應卷次加「續」標記。準則收緊為一條：**希臘原典已佚、或拉丁是後世唯一的傳承管道時才進正文對照欄。**

已收且理由成立者：斯塔提烏斯《底比斯戰記》（底比斯循環希臘本已佚）、西塞羅《論神性》（克呂西波斯神學希臘原典已佚）、卡爾奇迪烏斯《蒂邁歐》譯註（十二世紀前西方唯一的柏拉圖創世論）、阿普列尤斯《金驢記》卷十一（唯一第一人稱入教皈依敘事，希臘文無對應物）、希吉努斯《傳說集》（補阿波羅多洛斯佚失段落的唯一材料）。

**不符合此準則的拉丁書不要收。** 例如純文學性的拉丁神話重述、後世改編。

## 6. 與《基督教大藏經》重疊：互見不合併

`/dazangjing` 的「前基督教大藏經‧前藏經藏」已收赫西俄德《神譜》、德爾菲神諭等，定位是「邊界劃分之前的原始啟示母體前驅」。在本藏經它們是**本經**。

**規則**：
- 用 `seealso` 欄串連，格式如 `'基督教大藏經‧前藏經藏‧創世神話部'`
- **不合併、不去重、不改動 `/dazangjing` 的既有資料**
- 同一部書在兩座圖書館各有其位置與功能，敘述邏輯不同，合併會兩邊都毀掉

目前已標互見者：Α 神譜（赫西俄德）、Β 丟卡利翁洪水、Τ 德爾菲神諭彙編。發現新的重疊就補 `seealso`，不要動另一邊。

## 9. 加東西的標準流程

1. **定歸卷** — 過 §4 準則：這材料屬哪一套宗教？再定卷（§3 兩個時鐘決定插入位置）。
2. **定狀態** — 過 §5 四級。若非 `whole`，先跑 [[hellenika-fragments]]（殘篇／敵證）或 [[hellenika-epigraphy]]（銘文／紙草）把 `via`／`place`／編號查實。
3. **定譯名** — 過 §8。
4. **寫條目** — `note` 一行必填；`intro` 依 [[hellenika-curate]] 的規範寫 100–200 字。
5. **驗** — `npx vue-tsc --noEmit -p .nuxt/tsconfig.json`（只看非 `scripts/` 的錯；`scripts/*.mjs` 有既存無關報錯）＋ `npx vitest run`。
6. **同步凡例** — 若動到體例，改 `pages/hellenika/about.vue`。
7. commit + push（見 [[feedback_auto_push]]）。
