# 博士論文計畫書

`/works/hcu-phd`（`writing_projects.kind='thesis'`）。正文 `public/content/works/hcu-phd-proposal.md`，送件檔由 `scripts/build_proposal_docx.py` 產生同名 .docx。

**題目**：《從彼岸向此岸的轉向：台灣佛教與基督教公共性之宗教史比較研究（1920–2020）》
**指導教授**：釋昭慧

## 三個定調的決策（改動前先讀）

**一、方法論是歷史學，不是宗教學。** 宗教學與比較神學的意義放到**第六章**才談，把歷史歸納命名為「人間宗教」。不要把希克／尼特／潘尼卡那套理論回顧提前到前幾章——先做歷史、後論理論，理論是研究的結果不是起點。這是整份計畫立論正當性的所在。

**二、題目只指認研究對象，不掛背景。** 東亞是第二章的前史（以既有研究綜合為主、不作獨立史料考證），所以**題目不列「東亞」**——掛進題目等於承諾一份不打算做的一手東亞研究，口委會照那個承諾要求。🚨 **題目的年代寫「（1920–2020）」，不是「1920年代–2020年代」**（2026-09-05 使用者定調）。

**三、兩條四人系譜是全書骨幹**：佛教＝太虛→印順→**傳道**→昭慧；基督教＝黃彰輝→宋泉盛→**王憲治**→黃伯和。四個位置對應「發動者—詮釋者—落地者—建制者」，這個同構是主要發現。傳道（妙心寺）與王憲治（台灣鄉土神學）研究最薄弱，也最有補白價值。

## 七章結構

一 緒論：研究方法與文獻回顧／二 東亞近代宗教變革：入世轉向的共同源頭（前史）／
三 人間佛教在台灣的發展／四 台灣本土神學的公共性發展／
五 跨域共善的實踐：戰後台灣佛耶對話與議題結盟／六 「人間宗教」的範式：歷史歸納與理論意義／七 結論。

🚨 **2026-09-05 改版**：舊版第五章專責兩線比較、佛耶交會放第六章。現行版把
**兩線比較併入第五章前兩節**，佛耶交會與議題結盟也在第五章（第三至五節），
**第六章只留範式命名與理論意義**（含「人間」作為空間場域、對宗教學／比較神學的意義、範式限度）。
理由：使用者定調的論述順序是「先東亞→再台灣兩線與對話→最後才理論總結」。
附錄二〈研究計畫指導目標〉的「對應章節」欄位（台灣耶佛對話＝第五章）即依此章序。

🚨 **兩條四人系譜不是代表性取樣**，是切入「宗教公共性如何生成」的**路線取徑**。
凡提及系譜處都要有這個限定語（緒論（四）、研究目的其二、研究設計（五）（六）、
表一附註、預期成果、結論皆已寫入）。寫成「台灣佛教／基督教即是如此」會被口委抓。

## 送件格式

體例照系上原 Word 檔，**再對齊助學金表單 `02-論文計畫書(docx).docx` 明列的八項**。

🚨 **版面（2026-09-05 使用者定調，論文的一般規定）**：
正文一律**新細明體**、**首行縮排兩個字**（`Pt(24)` ＝ 12pt×2）；**只有引文用標楷體**
（markdown 寫 `> `，builder 會排成標楷體、左右各內縮兩字、首行不縮排）。
🚨 別再照《張辰瑋，論文研究計畫》「量測」版面——那份檔案自己格式就不一致
（261 個長段落裡只有 4 段有縮排、字型多半沒設），照它量會得到「整篇標楷體、不縮排」的錯誤結論。

段落順序（照表單逐字排）：
封面 → 摘要 → 關鍵字 → **Abstract** → **Keywords** → **目錄** → **圖表目錄** → **前言**
→ 一 研究背景與問題意識 → **二 研究目的** → 三 文獻回顧與探討 → 四 研究設計：方法與範圍
→ **五 研究時程（在論文架構之前）** → 六 論文架構（章節安排）→ 七 預期研究成果與貢獻
→ 八 結論 → 參考書目 → **附錄　八位人物主要著作一覽**（只有這一個附錄）。

**篇幅**：正文（摘要到結論、不含參考書目與附錄）約 **一萬五千多字**（現行 15,843 中日文字元）。
**摘要中文不得超過 500 字**（現行 419 漢字），且**不提章次**——這是計畫，章還沒寫。
🚨 **論文架構那一節不要膨脹**：每節說明 55–85 字、不加「章旨」段落，
整節控制在 2,900 字上下（曾寫到 4,459 字被退）。
🚨 **文獻回顧不要寫「缺口：」段**，使用者不要這種寫法；研究缺口在研究目的與預期成果講。
🚨 **附表下不要寫工作流程**（「完整目錄待赴某館查閱後補齊，此為第一年工作項目」之類）——
那是我的流程不是他的資料來源。資料來源一行，放腳註。
🚨 **全書只有八張表**，就是附錄那八張著作表（表一～表八），每張各自起一頁（`TABLE_PAGE_BREAK`）。
緒論裡那張「兩條系譜的四個歷史位置對應」已刪；十個月工作計畫那張也不放，因為使用者
另外寫了〈研究計畫指導目標〉一文單獨送件，計畫書只在研究時程末尾指過去。

`scripts/build_proposal_docx.py`：A4／頁邊 2.54cm／12pt／行距 1.5；`#` 主標 18pt 置中、
`##` 14pt、`###` 13pt；參考書目自動改懸掛縮排；「摘要」之前一律置中視為封面。
**第二個參數其實被忽略**，輸出固定是 `<輸入檔名>.docx`，要改名自己 copy。

**分頁**：`PAGE_BREAK_BEFORE`（Abstract／目錄／圖表目錄／前言／參考書目／附錄）＋
`TABLE_PAGE_BREAK`（表二～表九）。分頁設在標題段的 `page_break_before`，
**不要插只帶分頁符的空段**——會留下空行，標題落在頁首時還會多一整頁空白。

🚨 **目錄頁碼一律實測，不准估**；送出去的 .md 必須是**頁碼已填的那份**
（`build_and_page.py` 產的 `hcu-phd-proposal-final.md`），不要把還帶 `@P:` 佔位標記的組裝檔當成品。
🚨 **組裝腳本不可讀「已改版過的」計畫書當素材**（它的目錄含 `@P:` 標記，
`index('## 五、研究時程')` 會先命中目錄那一行）。留一份原稿，或從 git 取。
🚨 頁碼比對三個坑：①用整行相等，不能 startswith（會被目錄頁自己騙到）
②目錄與圖表目錄**整頁跳過**，否則表題會匹配到目錄那一行
③表題後面跟著上標註號，比對前要去掉行末數字。

```bash
python -X utf8 scripts/build_proposal_docx.py <輸入>.md
powershell -File scripts/docx2pdf.ps1 -Src <docx> -Dst <pdf>
```

## 學術註釋（國史館體例）

2026-09-05 補上，現行 24 條，一律從既有參考書目轉寫，不引入書目沒有的著作：
`作者，《書名》（出版地：出版者，年），頁碼。`／`作者，〈篇名〉，《刊名》第N期（年），頁X-Y。`
掛在文獻回顧四小節的各個子句、研究設計的三大史料群、緒論的兩處事實陳述。
參考書目末補「五、網路資源」一節。附錄各表的資料來源**不走註腳**，直接寫在表下 ＊ 行裡。

🚨 **註文不能長**：一條註文超過約 150 字，LibreOffice 轉 PDF 就會把文件最後一頁整個吃掉
（docx 本身完整、只有 PDF 少一頁，且門檻浮動）。所以①註文拆短、一條三四筆為限
②**PDF 一律改用 Microsoft Word 轉**（`docx2pdf.ps1`，Word COM `SaveAs2(..., 17)`），不要用 soffice。
Word 排得也比 LibreOffice 緊，同一份文件 Word 51 頁、LibreOffice 57 頁，
所以**頁碼一定要拿 Word 轉出來的 PDF 量**。
🚨 註腳文字不吃行內標記，英文書名別加 `*`，會原樣印出星號。

## 🚨 使用者手改過之後：改 .docx，不要從 markdown 重出

2026-09-05 起送件檔的**正本是 Drive 上那份 .docx**，使用者會直接在 Word 裡改（改寫段落、
換節名、加頁首頁碼、刪節）。要再動它時**不可以從 `hcu-phd-proposal.md` 重新產生**——
那會把他的手改整個蓋掉。工具是 `c:/tmp/thesis_rewrite/patch_user_docx.py`（就地改 XML）：
補腳註、補分頁、重算目錄頁碼，正文一字不動。

寫這種腳本的三個坑：
1. **一定要用 lxml，不能用 xml.etree**。ElementTree 重新序列化會把 document.xml 的
   命名空間宣告（w14／mc／wp…）打壞，Word 直接報「檔案似乎已毀損」。
2. **SRC 與 OUT 不能是同一個檔**。repack 一邊讀一邊寫會把 zip 寫成 truncated header。
3. **`pageBreakBefore` 要插在 `pPr` 的前段**（CT_PPr 的順序是 pStyle→keepNext→keepLines→
   pageBreakBefore→…），位置錯了 Word 會靜默忽略。

頁碼實測的額外兩個坑（使用者加了頁首頁碼之後才出現）：
**每頁抽出來的第一行都是純數字**，所以判斷「這頁是不是目錄頁」與比對標題前，
要先濾掉純數字行；而且「目錄」「圖表目錄」的標題可能落在前一頁頁尾，
找它們自己的頁碼時要掃全部頁面找「整行剛好等於它」，不能只在目錄頁裡找。

使用者的手改沒有回寫）。Drive 上的 .md 已依使用者指示刪除，只留 docx＋pdf。
