# 解說影片：實拍片頭＋無限黑板＋預告片混剪

一句話：**腳本 → cues.json → 黑板 → 影片**。所有東西都吃同一份 `cues.json`，
所以改腳本、改時間、改風格、改哪幾句切預告片，都不用重排版。

腳本在 `scripts/board_video/`，素材與成品在 Drive
`G:\我的雲端硬碟\創作\影片創作\<專案名>\`（成品不進 git，見 docs/repo-hygiene.md）。

## 形式怎麼定的（別再從頭想一次）

查過現在的做法後，中文解說影片大致三條路：

| 路線 | 代表 | 我能不能做 |
|---|---|---|
| 手繪黑板動畫 | [RSA Animate](https://www.youtube.com/watch?v=zDZFcDGpL4U) | 一半。**那是真人畫的**（Andrew Park 在實體板上手繪），我不會畫插畫 |
| 劇照＋大字卡（簡報式） | [超級歪 SuperY](https://www.youtube.com/watch?v=SsdaWUWHoCo) | 可以，素材已到位 |
| 一張大地圖＋鏡頭遊走 | [Domain of Science](https://www.youtube.com/watch?v=OmJ-4B-mS-Y) | 可以，但地圖本身該是插畫 |

**使用者定案＝paper 風格 ＋ 混剪 ＋ 手繪描出效果**：主體走黑板與大字卡，
講具體劇情時切劇照／預告片動畫，抽象概念時切回黑板用線稿描出來。

VideoScribe、Doodly 那類工具其實也不是即時作畫，是把素材庫裡**預先畫好的線稿**
用描繪動畫播出來。所以「手畫出來」我做得到，差別只在圖是誰畫的：

- 向量線稿（OpenMoji black 版，`<path fill="none" stroke>`）→ 逐筆 `stroke-dashoffset` 描出來
- 點陣圖（使用者可以用 GPT 生黑白圖給我）→ 遮罩由左往右漸進顯現、手跟著邊緣走
- 中文字 → `clip-path: inset()` 由左往右寫出來，不需要筆順資料

## 一支影片的完整流程

1. **抽腳本**：docx → `腳本.txt`（一段一行，段落索引就是後面對應節點的鍵）。
2. **設計板面**：`spec_chiikawa.py` 這類 spec 檔，四件事——
   - `NODES`：位置、標題、重點條目、類別（決定配色）、`icon=`（線稿檔名）
   - `EDGES`：哪兩個節點要用粉筆線串起來
   - `PARA_NODE`：**第幾段講到哪個節點**（最關鍵的一張表）
   - `CHAPTERS`：哪一段是新的一幕（決定幕名與擦板轉場）
3. **切 cue**：`make_cues.py` 依句末標點切句、合併短句、估時長（預設 4.5 字/秒），
   產出 `cues.json` 與細流表 xlsx。
4. **收素材**：`fetch_cc_assets.py`（CC 音樂＋公有領域圖）、`extract_shots.py`
   （預告片分鏡截圖＋接觸表）、`make_sfx.py`（自己合成音效）、
   `make_memes.py` / `make_shot_memes.py`（名畫反應圖、吉祥物卡、預告片畫面梗圖）。
5. **給使用者看版面**：`build_board_preview.py` → 單檔 HTML，可拖曳縮放、切風格、
   看講述順序與鏡頭路徑、點節點看那格講什麼。**他看得到才講得出要改哪裡。**
6. **挑配圖**：看接觸表，編號填進 `suggest_shots.py`，重跑 `make_cues.py`。
7. **指定 B-roll**：哪幾條 cue 要切預告片寫進 `素材/預告片/broll.json`。
8. **出片**：`python assemble.py --all --out 成品.mp4`（黑板段＋預告片段混剪），
   或只要純黑板就 `node render.mjs --theme paper`。
9. **片頭**：`make_opening.py`（見下）。
10. **接成全片**：`join_parts.py 片頭_v1.mp4 本體_第一幕起.mp4`。
    片頭已經把序幕講完了，所以本體要從**第一幕**開始渲（`assemble.py --from <第一幕的 t>`），
    否則序幕會講兩次。
11. **驗段長**：`check_sync.py --from <第一幕的 t> --video <全片>`。每一段都要對得上它
    該佔的 cue 秒數，不然音效會整批偏掉（見下「聲音」一節）。
12. **混音**：`mix_audio.py --video out/<全片>.mp4 --offset <片頭長 − 第一幕的 t>`。
    **出片那幾支一律無聲**，音樂與音效全在這一關補。
13. **（可選）進 AE**：`build_ae_jsx.py` → AE 執行指令碼，節點、連線、鏡頭關鍵影格全帶進去。

## 混剪：黑板段與預告片段怎麼拼

`assemble.py` 的核心是「**一條 cue 佔的秒數不變**」：某條 cue 標成 B-roll 時，
那幾秒改放預告片畫面，黑板段就跳過那段時間，總長度不動、字幕不用重算。

```json
// 素材/預告片/broll.json，key 是 cue 編號，shot 是接觸表左下角的 [NNN]
{"63": {"shot": 394}, "65": {"shot": 388, "speed": 0.8}}
```

- 黑板段 `render.mjs --nosub` 逐格畫；預告片段 ffmpeg 直接剪，兩邊都疊多馬豬。
- 全部 concat 完才燒一次字幕，樣式才會一致。
- 預告片本身帶著片名 logo 與上映日期，介意的話在 `clip_segment` 的 `crop` 放大一點推出去。

## 聲音：音樂床與音效床（`mix_audio.py`）

`render.mjs` 與 `assemble.py` 出來的每一段都是無聲的（都帶 `-an`，兩邊串流規格才對得
起來直接 concat），`join_parts.py` 再替沒有旁白的本體補一條 `anullsrc` 靜音。
**所以素材收齊不等於片子有聲音**：音樂與音效是最後獨立混上去的一關，漏掉這一關，
片子看起來完全正常、只是一路安靜到底（用 `volumedetect` 一驗就知道：整片 mean 低於
−40 dB 就是只有片頭那段實拍在響）。

`mix_audio.py` 吃的還是同一份 `cues.json`，所以配樂不需要重渲影片：

- **音樂**一幕一段，分組決定曲風類別（細流表 `bgm_by_group` 那張表），同類別內輪流
  換曲、幕與幕之間交疊 1.5 秒。配置寫在 `素材/音樂/配置.json`（一幕一列），
  要換曲或讓某一幕安靜就改那份檔案再跑一次。
- 各曲先 `loudnorm` 拉到 −23 LUFS 再混：CC 音樂彼此響度差十幾 dB，不拉齊會忽大忽小。
  交疊處兩首相加會撞到 0 dB，床輸出前一律 `alimiter`，否則 16-bit 寫出去就是削平的。
- **音效**的落點直接從 cue 的欄位長出來（`chapter` 換幕→擦板＋粉筆、`travel` 鏡頭移動
  →whoosh、`first_visit` →寫字、`reveal` 增加→短粉筆＋叮），對照表是
  `素材/音效/合成/說明.txt`。序幕那段是實拍原音，`--sfx-from` 之前不鋪黑板音效。
- 旁白用 `sidechaincompress` 讓音樂自動退讓，**本體還沒錄旁白時這一關等於不作用**，
  等他錄完再混一次就好，參數不用改。
- `--offset` 是「cue 時間 → 影片時間」的位移：全片＝片頭（79.87s）＋本體（從第一幕
  t=67.83 起），offset = 12.04。只混本體就給 0。

## 片頭（實拍 → 海報 → 序幕）

順序是使用者定的：**問好之後海報才出現**，然後接序幕正文。
他錄的開場白最後一句正好是「所以我們要講的是——」，海報就接在那一刀上。

- 先跑 `transcribe_takes.py` 拿逐句時間戳，用它決定頭尾切掉多少、哪一句要切畫面。
- 正文那一分鐘不會一直盯著同一顆布偶：在指定句子切到劇照／預告片／自製暴雷卡再切回實拍。
  **聲音不受影響**，因為畫面是先 concat 成無聲片，音軌整段最後才 mux 回去。
- 字幕文字不要直接用 whisper 的結果（會出現「吉利卡挖」「多瑪珠」「等牙便術」），
  在 `SUBS_GREET` / `SUBS_PROLOGUE` 手動訂正，時間戳照用。
- 多支 take 要挑時：先看音量（`volumedetect` 抓出無語音的空鏡）再看轉錄內容，
  別只看縮圖——五支的畫面幾乎一模一樣，差別全在講了什麼。

## 黑板上的動畫是怎麼做的

全在 `board.html`，時間軸吃 `cues.json`，`seek(t)` 是純函式（同一個 t 永遠同一畫面）：

- **寫字**：標題與每個條目包一層 `.rv`，`clip-path: inset(0 X% 0 0)` 由 100% 收到 0%。
- **描線**：`.icon svg` 裡每條 path 量 `getTotalLength()`，設 dasharray 再收 dashoffset，
  一筆畫完接下一筆（前一筆的 72% 就開始，才不會一頓一頓）。
- **手**：畫面上只有一隻 `#hand`（OpenMoji 270D）。正在寫的字用
  `getBoundingClientRect()` 算筆尖 x，正在描的線用 `getPointAtLength().matrixTransform(getScreenCTM())`。
- **擦板**：換幕時一道半透明斜向漸層掃過 viewport。
- **鏡頭**：`camFor()` 用**量到的**寬高（`_w`/`_h`）算縮放，可用高度只算到字幕帶上緣（820px），
  中心也上移到 y=470，卡片才不會被字幕壓到。

## 踩過的坑（會再犯的那種）

- **動手前先把使用者的素材夾整個看過一遍**。這次直接去抓預告片與公有領域圖，卻沒發現
  `創作\影片創作\` 底下早就放了 多馬豬卡通圖／多馬豬照片／電影劇照／影片封面／
  作者被說毫無人性 這些自備素材，還自己拿別的專案的粉紅豬頭貼當吉祥物，認錯了主角。
  **自備素材永遠優先於我去網路上找的東西**；吉祥物、封面、頻道 logo 這類識別只能用他的。
- **鏡頭的水平中心也要用量到的寬度**：`camFor()` 的縮放早就改吃 `_w` 了，`cx` 卻還留著
  `node.x + node.w / 2`（規格寬）。卡片實際比規格窄五、六百 px，於是鏡頭對著卡片右邊的
  空白，卡片被推到畫面左緣、左半截切出畫面——32 張卡有 24 張中彈，平均偏左 467 px。
  **這種「一半修好」最難發現**：畫面看起來正常，只是東西不在正中間。改完拿
  `getBoundingClientRect()` 量每張卡在自己 cue 上的螢幕座標驗一次（中心應該都是 960）。
  連線端點（`edges` 的 `ax`/`bx`）同一個毛病，一起改。
- **音樂音效收好了不等於片子有聲**：素材夾有 21 首曲子、12 個音效、細流表也標好了，
  但出片管線從頭到尾沒有任何一段在混音，整支片只有片頭那 80 秒實拍在響。
  補一關 `mix_audio.py`，出片後用 `volumedetect` 驗一次整片音量。
- **段長要驗，不然音效整批偏掉**：音樂音效照 cues.json 的時間鋪，影片卻是一段一段接的；
  某一段渲短了，畫面完全正常，但後面每一句的音效都往前偏、而且愈後面偏愈多。
  `check_sync.py` 逐段比對「該佔幾秒 vs 實際幾秒」。
- **卡片別做成「條列清單」**：一格塞四到六條字就會像投影片講義在移動，不像解說動畫。
  一格只留關鍵詞、配一張圖，字留給旁白講。卡片寬度用 `width: max-content`
  （spec 的 `w` 只當上限），不然短內容會被拉成一條長條。
- **`cv2.imwrite` 遇中文路徑會靜默失敗**：偵測到鏡頭、印出張數，但一張都沒寫出來。
  改用 `cv2.imencode` + `Path.write_bytes`。這條對 Drive 上所有中文資料夾都適用。
- **節點沒被任何段落指到就等於不存在**：板面上設計了四個角色節點，`PARA_NODE`
  漏掉，整支片都不會出現。改完 spec 一定要驗
  `{c['node'] for c in cues} == {n['id'] for n in nodes}`。
- **鏡頭要對「量到的尺寸」不是「規格尺寸」**：spec 的 `w`/`h` 只是版面預留，
  實際卡片通常小很多，拿規格值對焦會對著一大片空白。init 時量 `offsetWidth/Height`。
- **`round(0.375) == 0`**：條目浮現數用四捨五入會讓節點第一次出現時「有框沒字」。
  用 `ceil` 並下限 1。條目還沒寫到時連項目符號都要藏（`li` 整個 opacity 0），
  不然會看到一排空的「•」。
- **ffmpeg 子行程的結束事件要在 `spawn` 當下就接**：等到最後才 `ff.on('close')`，
  事件早就發過了，`await` 永遠不落地，node 以 **exit code 13**（unsettled top-level await）
  收場——而 ffmpeg 其實有寫完檔，所以檔案看起來正常、只有呼叫端以為失敗。
- **`ffprobe` 的 JSON 有中文檔名時 `text=True` 會爆掉**：Windows 預設拿 cp950 解，
  讀取執行緒丟 UnicodeDecodeError，但 **returncode 還是 0、stdout 變成 None**。
  所有 `subprocess.run` 一律帶 `encoding="utf-8", errors="replace"`。
- **`subtitles` 濾鏡吃不了磁碟代號**：`subtitles=G:\...` 的冒號會被當參數分隔。
  切到字幕檔所在目錄（`cwd=`）用相對檔名。
- **單張 PNG 餵給 fade 會被凍住**：`-i card.png` 沒有 `-loop 1` 就只有一格，
  `fade=alpha` 把那一格停在 alpha=0，overlay 出來整張看不見（標題卡整段消失）。
  疊圖卡一律 `-loop 1 -framerate 30 -t <長度>`。
- 🚨 **抓素材沒設授權過濾＝整批不能用，而且完全看不出來。** 人魚島那批 27 首 CC 音樂裡
  **18 首帶 NC（非商業性）、9 首帶 ND（禁止改作）或 SA**，真正可商用又可改作的只有 2 首；
  片子照樣做得出來、聽起來也沒問題，但一開營利就整批違約。`fetch_cc_assets.py` 當初只看
  「是不是 CC」沒看「是哪一種 CC」。**現在配樂一律走 `scripts/music_library.py` 建的共用
  配樂庫**（incompetech／Kevin MacLeod，1,442 首，全部 CC BY 4.0、全部純器樂，官方 FAQ
  明文允許 YouTube 營利），`配樂庫.html` 可以逐首試聽再挑。舊素材夾裡那批留著當參考，別用。
- **音樂要「柔」不是只要「小聲」**：旁白要壓在上面時，除了壓低音量，還要在 2 kHz 人聲頻段
  挖 3.5 dB、8 kHz 以上收 4 dB（`mix_audio.py` 預設就這樣做，`--no-soften` 可關）。
  挑曲時把 Bouncy／Humorous／Action／Driving／Grooving 與帶鼓的整批排除，BPM 壓在 105 以下。
- **Openverse 匿名額度極低**：連續查會 401/429，音效那批跑 20 分鐘一個檔都沒下來。
  音樂改走 ccMixter（要帶 `Referer: https://ccmixter.org/` 否則檔案 403）與
  archive.org netlabels；音效乾脆自己合成（`make_sfx.py`，純 stdlib 算 whoosh／叮／
  重擊／粉筆／擦板），原創零授權風險。
- **archive.org 會給整張專輯的單檔**：抓到 194MB 的 mp3。抓完要按大小過濾（>30MB 丟掉）。
- **memes.tw 擋機器人（403）**：梗圖改本機合成——拿預告片分鏡當模板加粗白字黑描邊
  （`make_shot_memes.py`），跟影片其他部分同一套「評論引用」基礎。
- **yt-dlp 版本落後就是 403**：YouTube 一改動就掛，先 `pip install -U yt-dlp` 再說。

## 時間軸與配音的關係

第一版時間軸是估算的（`--cps`）。錄好旁白後兩條路：整體語速微調
（`make_cues.py --cps 4.2`），或用 whisper 逐句時間戳改寫 `cues.json` 的 `t`／`dur`
（片頭那段就是這樣做的）。鏡頭運動、寫字、描線、連線動畫全部由 `cues.json` 驅動，
重跑 render 即可，版面不用動。

## 版面固定元素

- **多馬豬**（頻道主持人＝棕色布偶＋單眼鏡＋菸斗）圓形去背固定在左下角，整支片都在；
  字幕左邊留 340px 讓開他。
- **開場封面卡**：`素材/封面/影片封面.png` 全屏停 3 秒後淡出（`--cover 秒數`，
  只在 `--from 0` 時出現）。片頭那支則是接在開場白之後。

## 三種風格

`--theme chalk`（綠黑板粉筆，標楷體）／`paper`（米色手帳，卡片＋色邊，**使用者選這個**）／

## 素材從哪裡來（別人怎麼做、我能拿什麼）

完整清單與各家頻道的做法在 [references/footage-sources.md](references/footage-sources.md)，
網頁版報告在 <https://claude.ai/code/artifact/48cdb205-821c-4a4d-89e0-0808c5bde2a7>。三件事：

- **想知道別人怎麼做，先抓說明欄**：`yt-dlp --skip-download --print "%(description)s"`。
  Veritasium 的動畫師名單、素材商、NASA 與超級電腦中心的視覺化來源全寫在裡面；
  超粒方的剪輯與腳本分工、Cheap 的參考資料與老照片出處也是。比看「十大推薦」可靠得多。
- **歷史題材的共同處境是沒有影像**，各家解法就是各家風格：Cheap 用世紀帝國遊戲畫面、
  臺灣吧全部自己畫、歷史哥乾脆不做畫面。本專案的無限黑板屬於「自畫」但成本低得多。
- **自建素材庫**：`scripts/heritage_images.py` 把國家文化記憶庫的開放影像抓進
  Drive `創作\影片創作\_素材庫\國家文化記憶庫\`（依主題／類別分夾，附 manifest 與
  可直接貼說明欄的 `授權標示.txt`）。**那個開放資料 API 只釋出可開放授權的一批，
  一筆 NC、一筆 ND 都沒有**——全 37,667 筆／58,028 張的實際分佈是
  CC BY 48.1%／PDM 30.8%／OGDL 14.2%／CC0 4.8%／CC BY-SA 2.0%，
  所以**全部可商用**，差別只在 CC BY 與 OGDL 必須標示、PDM 與 CC0 免標示。
  CC BY-SA 會傳染整支影片，抓下來會自動隔離進 `_相同方式分享SA/`，預設不要用
  （本機那批已刪，需要時才 `--get`）。
- 🚨 **前台不是這樣**：memory.culture.tw 前台約半數只到「非商業性使用」，那些根本
  不在這支 API 裡，而且從圖片本身看不出來。**要補圖走 API，別上前台右鍵存。**
- 🚨 **CC 不保證肖像權**：人物類多是人像，著作權開放≠肖像權開放；館方後設也可能
  標錯。放進影片前看一眼該筆的 `tcmbUrl` 原頁。
- **2026-09-10 改成隨選**：全量要 ~82 GB，但會用到的沒那麼多，而「找得到」只靠
  metadata（37,667 筆帶標題描述關鍵詞授權與原圖網址，才 77 MB）。**影像只留
  `民俗與宗教`（10,989 張／15.3 GB），其餘五個主題已刪、排程 `KGL_Heritage_Images`
  已 Disable。** 要用別的主題就：

      python heritage_images.py --search 媽祖 遶境     # 查本機 metadata，多詞＝AND
      python heritage_images.py --search 媽祖 --get    # 只把查到的抓下來

  `授權標示.txt` 現在只列本機真的有的（以前是全量出，改隨選後那樣會列出根本沒抓的）。
  比對要連 path 一起比，光比 url 會錯：**761 個 URL 跨主題重複**，同一張圖同時掛在
  兩三個主題底下。這條也讓 `--get` 不會靜默跳過一個本機其實沒有的檔。
  順手清掉的：`_metadata/jobs.jsonl`（41 MB，只寫從不讀，一秒可重算，已不再產生）。

## 授權規矩

- 官方預告片畫面＝評論用途引用，出處寫進 `授權標示.txt`。**不抓盜版片源。**
- CC BY 音樂音效必須在說明欄標作者與授權連結（`fetch_cc_assets.py` 會自動產這份文字）。
- **Content ID 假申訴在公有領域素材上很猖獗**（NASA 官方頻道自己都被下架過）：
  下載當下就存來源網址、授權頁截圖與日期，收到申訴直接貼。
- 台灣的界線在著作權法 §52「引用」與 §65 四款基準：**解說要是主體**。谷阿莫案 2020 年
  和解賠約 100 萬，他之後的頻道再也沒有一支電影解說——那個型態被那場官司終結了。
- 網路流行梗圖多半版權不明，不自動抓；改用公有領域名畫、自家吉祥物、預告片畫面。
- 公有領域圖抓回來要看過再用：搜「八百比丘尼」拿到的是現代神社石塔照片，
  換成北齋的人魚圖才對；搜「后稷」拿到的全是伏羲。
