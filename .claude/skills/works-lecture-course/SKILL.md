## 🚨 簡報按週次出，而且投影片上不准出現章號

`course_slides_weekly.py` 才是現在出簡報的入口（`course_slides_pptx.py` 退居渲染器）。
它把既有「八次×兩章」的 `course_slides_data*.py` 依章拆開，再照 `course_schedule.py`
的週次表重編組，**37 份**一次出齊：BBE275 12 份、BBE150 12 份、PPA066 7 份、PPA001 6 份。
（演講與參訪那六週不排課程單元，所以不出簡報。）

**章號是使用者自己的備課編號、不發給學生**（2026-09-07 定調），所以四個地方都要擋，
少擋一個就會有一頁把「第十四章」投影出去：

1. 分節頁的 `no` 欄（`'第一章‧第三段'` → `'第三段'`）
2. 副標——**可能是結尾的 kwargs dict，也可能是位置參數的字串**，兩種都要清；
   只清一種的話另一種會被下一條的改寫器變成「其他單元」，比留著還糟
3. 正文的交叉引用（「見第十四章」）——不能直接刪，會把句子砍斷；
   依前後關係換成「前面的單元／後面的單元／本單元」
4. 沒帶數字的說法（「每一章」「本章」「各章」），正規表示式抓不到，用字串表換
5. 課末書目頁的副標（原本寫「第 1 章講義所附之參考資料」）

改完一定要跑一次全量稽核（把三十七份掃過找 `第X章`），別只看單一份。

### 🚨 投影片上不只不准有章號，連「講義」「本書」都不該出現

使用者 2026-09-09：**「我在課堂上沒有在用講義」**。投影片是課堂上唯一在看的東西，
叫學生去翻一份他們手上沒有的東西沒有意義，自稱「本書」也一樣。所以另外三處要清：

1. 開場互動第一頁副標「先不查資料、**不翻講義**；⋯」→ 去掉「不翻講義」
2. 課末書目頁副標「本次上課單元的參考資料；**完整註釋見課堂講義**」→ 只留前半
3. 正文裡的「本書」→「本課程」（`course_slides_weekly.BOOK_SELF`）

🚨 第 3 條**不能無差別取代**：「一本書」「同一本書」是量詞，《日本書紀》是書名。
正規表示式要排掉 `(?<![一那這同日])本書(?!紀)`。改完拿成品 pptx 掃一遍驗證——
第一次掃出 197 處（其中 153 處只是那兩句固定副標），第二次才確認只剩合法的用法。

課末書目裡若引到使用者自己那本講義（例「張辰瑋，《宗教歷史地理學》（授課講義，
十七章）」），那是**書目引用**不是叫學生去翻，照留。

### 另外三個踩過的坑

- **開場互動題庫的索引不是週次。** `OPENERS[course][n]` 的 n 是「第 n 次上課」＝第 2n−1、2n 章。
  照週次直接傳會拿到別章的題目（第 5 週曾拿到一神論的題目而內容是泛神論），
  要用本單元頭一章回推 `(min(chs)+1)//2`。

  掛到日間部就是錯的。已改由 `intro_slide()` 依各課自己的資料重生。
- **演講與參訪那六週**（BBE275 10/7、11/4；BBE150 10/7、11/4；PPA066 11/7；PPA001 11/1）
  **一律不排課程單元，也不出簡報**（使用者 2026-09-07：「有演講時就不能排課」）。
  `course_schedule` 裡那幾列的章號欄是空的，`units()` 直接跳過。

## 一、講義章節

章節是 fragment（`_head.html` ＋ `chNN.html`），由
`node scripts/assemble_lecture_books.mjs` 串成單一書檔供 `/works` 閱讀器讀。
單次上課的可列印 Word 由 `course_handout_docx.py` 出（`works_series_docx.py` 做整本，
這支做一次上課的份量，且支援 `<table>`——這幾本大量用對照表）。

### 註釋與書目的寫法

正文註號、章末註釋、章末書目三段固定：

```html
<sup class="footnote-ref"><a href="#fn-ch08-3" id="fnref-ch08-3">3</a></sup>
<div class="footnotes">
  <div class="fn-item" id="fn-ch08-3">…<a href="#fnref-ch08-3" class="footnote-backref">↩</a></div>
</div>
<h3>參考資料</h3><ul>…</ul>
```

🚨 **改完一定要跑 `python scripts/lecture_footnote_check.py`**（省略參數＝四本全查）。
它抓兩類**不會報錯、只會變成「看起來正常的壞頁面」**的問題：

1. **孤兒註釋**——`fn-item` 有、正文沒有對應註號（或反過來）。
2. **註號亂序**——marker 不是 1..N 依序。在既有註釋**之間**插入新註最容易踩到。

在中間插註之後用 `python scripts/lecture_footnote_renumber.py <檔案...>` 收尾，
它會重編註號並同步 backref；手工改號幾乎一定會漏掉 backref，而漏掉的結果是
讀者按了註號跳不回正文。

現況（2026-09-04）：四本共 **1,098 條註釋／962 筆書目**。

### 版面：標題下那條線與頁碼（2026-09-09 大修）

使用者看完三十七份的回饋是「很多線都壓到字了」。查下去是**每一張有副標的頁都中**：

- 標題下那條細線原本畫死在 3.80 cm，而標題框只要長到兩行、或掛了副標，
  字就長到線以下——線正好橫過副標中間（線 y=108pt、副標 y=87–112pt）。
- 稽核當時回報零問題，因為線是**向量圖形**，不是文字也不是圖片，三項檢查全部漏看它。

改法：`title_block()` 先量標題實際佔幾行（`字級 × 行距 × 1.2`，1.2 是 PowerPoint 的
中文字型行高係數，拿 40pt 單行標題回推與 PDF 量到的一致），線與內文頂都往下讓。
標題盡量壓成一行（40 → 最小 32pt），因為多一行就把線與內文一起往下推 2 cm。
🚨 `slide_title()` 現在**回傳內文該從哪裡開始**，每一支 `s_*` 都要吃這個回傳值；
`split_long()` 判斷拆不拆頁也必須走同一個 `body_h()`，否則「該拆的沒拆」會靜靜擠成小字。

`course_slides_audit.py` 補上第四項檢查「線壓字」。改版前 389 處，改版後 0 處。

**頁碼＝這一張在檔案裡真正的位置**（使用者自己在第 1 週那份手改的）。舊版編的是
「內容頁的序號」，封面、開場互動、自我介紹、分節頁都不算，於是右下角寫 12、
PowerPoint 的頁數是 17，有人說「第 12 頁」時對不上。現在等全部投影片生完再照位置編。

### 配圖：`course_slide_illustrate.py`

使用者第二個回饋是「圖有點太少」——原本一份三十幾張只有三到十張圖。
圖庫本身早就用光了（wr 73 張用掉 71 張），所以是**先補圖庫、再配頁**：

1. `course_slide_images*.py` 各補一批 Commons 條目（wr +54／ch +41／sl +34）。
2. `course_slide_illustrate.py` 是「投影片標題 → 圖片 key」的**指名對照表**，
   渲染時把對得上的 `bullets` 頁換成 `imgbullets`（左文右圖），**不多生一張投影片**。

🚨 **指名，不做關鍵字比對。** 模糊比對一定會把「儀式」的圖配到別頁去，而且看起來很正常。
🚨 **配圖擺在拆頁之後**（`prepare()` 的順序是併頁 → 拆頁 → 配圖）。擺前面的話，
   條目多的頁在配圖那一關就被擋掉——它本來就要拆成兩頁才裝得下——於是整章一張圖都配不到。
   量過：wr 五十五個配圖點只有**零個**過得了關；改成拆完再配之後是二十五個。
   拆出來的第一半留著原標題、對得上表，圖就掛在第一半上，也不多生投影片。
🚨 文字欄寬度是**由窄到寬試**（`IMG_TEXT_W = 17.0 / 19.5 / 21.5 / 23.5`）：
   內容少就給大圖，內容多就縮成小張插圖。原本寫死 17 cm，等於只有本來就很空的頁配得到圖。
   `img_layout()` 是唯一來源，`s_imgbullets` 與 `split_long` 必須吃同一個。
🚨 **圖說框高不能寫死。** 原本固定 1.0 cm（約兩行）；圖欄一變窄，同一句圖說排到三行就
   整段掉到頁尾線下面。改成 `caption_size()` 照寬度算幾行、超過三行才縮字，圖框跟著讓。
🚨 改對照表之後跑一次「標題對不對得上」的檢查——打錯一個字就是靜靜不配圖，不會報錯。
🚨 `course_slide_images.FOLDERS` 的資料夾名要跟 `course_slides_pptx.COURSES` 一字不差。
   國文那一格曾漏掉「115-1_」前綴，`--course=sl` 會另開一個空資料夾把圖倒進去，
   渲染時再回報「缺圖」——檔案明明抓下來了，就是不在渲染器找的地方。

「」『』《》內的字、全形對齊符號一律不准動，長度差超過 25% 也退件（版面是照字數估行的，

🚨 寫回原始碼走 `ast` 找字串節點、連**隱式相接的多段字串**一起換掉，不做文字取代——
有三百多條在原始碼裡是拆成好幾段寫的，純文字取代會整批漏掉。改完 `ast.parse` 驗一次。

🚨 **配圖對照表也要一起改**：它拿投影片標題當鍵，標題被潤飾掉一個字就靜靜對不上、

## 三、小考（線上＋紙本＋Kahoot）

```
python scripts/course_quiz_build.py --course=wr2|ch|sl [章號...]   # 省略＝十六章全出
python scripts/office_to_pdf.py "G:\...\教學\{課程}\小考"           # docx → pdf
python scripts/course_kahoot_xlsx.py [--course=ch] [次數...]        # 每次上課一份 20 題
```

`course_quiz_build.py` 一次產出**三件**：線上版 HTML（`{slug}/quizzes/{prefix}-chNN.html`
＋更新 `{slug}-quizzes.json`）、Drive 紙本考卷 docx、教師用解答卷 docx。Kahoot 匯入檔
從線上版 HTML 轉出，所以自動跟著走。

🚨 **題庫來源是 `scripts/course_quiz_data*.py`，小考 HTML 是產生物，不要直接改。**
踩過的坑：曾把選項打散做在產生出來的 HTML 上，結果 Drive 上的紙本考卷完全沒動到，
而且下次有人重跑 build 就會被還原。**所有題目與順序的調整都改在題庫或產生器。**
改完 docx 記得再跑一次 `office_to_pdf.py`，同資料夾的 PDF 不會自己更新。

🚨 **正解位置由產生器決定，且必須吃內容。** `balanced()` 舊版用一張只吃
「章號×題號」的輪轉表，於是三門課同一章的正解序列一模一樣（第一章都是 BABADDDDAB），
學生不必讀題就能猜。現在改成依 `md5(課程+章+題號+跳脫後的選項文字)` 排序：
只跟內容有關，所以**線上 HTML、紙本 docx、Kahoot 三者必然同序**，重跑也穩定。
驗算方式是拿 xlsx 的 C–F 欄與正解欄回頭比對題庫 HTML，480 題應全部一致。

Kahoot 的字數上限網路上兩種說法（120/75 與 95/60），取嚴的一組；超長的題目**不截斷**，
只列出來人工改短——截斷會把題意切壞。資料自第 9 列起，B 題幹、C–F 選項、G 秒數、H 正解；
匯入器若挑格式，把 B9:H 那塊貼進 Kahoot 自己下載的範本即可，欄序一樣。

## 五、第一堂課的分組測驗（世界宗教文化導論）

`/works/world-religions-intro/personality` —— 十六型宗教人格。二十道情境題，四個軸各五題
（單數題不會平手），交叉成十六型，同時當**四週分組報告的分組依據**。頁面在 `/works` 底下，
沒有掛 auth middleware，學生用手機直接開得了，不必登入。

四個軸：神聖在哪裡（天／地）・怎麼認識它（文／感）・在哪裡修（眾／獨）・怎麼看世界（入／出）。
結果是四個字（例「天感眾出・朝聖型」），旁邊畫成四爻的爻象——實線是前者、斷線是後者。

**十六型怎麼收成八組**：收掉「眾／獨」那一軸（`familyKey` 取第 1、2、4 個字），
剩下八個家族，每個家族配一個報告題目與三個切入提示。40 人剛好 8 組×5 人。

`stage === 'teacher'` 那一段是**教師分組工具**（首頁最下面那行小字進去）：把
「姓名　系級　四字代碼」貼進去就分好組。規則兩層——先照家族聚合、家族太小或滿了就併到
只差一個軸的鄰居（標黃），再做系級平衡讓每組至少兩位宗教系學生（`isMajor` 認「宗教」二字）。

🚨 **題目一句宗教都不提**（使用者定的）：問的是森林裡想遇到什麼動物、第一次約會去哪、
演唱會站搖滾區還是後面、中秋節烤肉時在做什麼——投射式的，答的人看不出自己在被歸類。
直接問「你覺得神聖是什麼」那一版被打回票，太像問卷。改題只要動 `QUESTIONS`，
每軸五題、`axis` 標對就好，計分與型別不必跟著改。

🚨 這門課 49 人裡有 8 位休學 1 位刪除，**實際 40 人**；其中餐旅系 24 人（六成，多為越南籍生），
純照測驗結果分組會整組都是餐旅系，中文報告帶不動——系級平衡那一層不能拿掉。

驗證方式：`node` 開 playwright 走完二十題並貼 40 人名單，稽核「8 組／每組 5 人／40 人不重不漏」。

playwright 別用 `waitUntil: 'networkidle'`，Nuxt dev 的 HMR 連線讓它永遠等不到。

## 🚨 題庫裡的 `<em>` 曾經三邊一起壞

題幹與選項會用 `<em>` 標原文詞（<em>gaga</em>、<em>odù</em>、<em>ceque</em>…）。
2026-09-09 發現這段標記**三種成品全部壞掉**，而且壞了很久沒人看出來：

| 成品 | 學生看到的 |
|---|---|
| 線上小考 HTML | 字面的 `<em>gaga</em>`（`html.escape` 把它變成 `&lt;em&gt;`，瀏覽器照字面顯示） |
| 紙本考卷 docx | 字面的 `<em>gaga</em>`（Word 不吃行內 HTML） |
| Kahoot xlsx | `&lt;em&gt;gaga&lt;/em&gt;`（轉換器只去標籤、沒有 unescape） |

修法各不相同：HTML 用 `rich()` 放行 `<em>` 其餘照跳脫；docx 在 `run_ea()` 用 `plain()`
把標記拿掉；Kahoot 的 `strip()` **先 unescape 再去標籤**。

⚠ **`balanced()` 的雜湊維持吃 `html.escape` 的原字串，不要跟著改**——
動它會讓 480 題的正解位置整批位移，等於全部重印。

## 🚨 版面跑版：五種成因，別用同一支扳手

2026-09-09 用 `course_slides_audit.py` 掃 37 份，來回七輪才歸零。教訓是
**「文字掉出版面」不是一個問題，是五個**，每次都要先**量 PDF** 再改，
不要看到數字沒降就繼續調同一個參數：

| 成因 | 症狀 | 修法 |
|---|---|---|
| 估算太樂觀 | 最後一兩個字掉到頁尾線下 | `FIT_MARGIN`（現 0.84） |
| 只拆一次 | 超過兩頁份量的內容拆完仍塞不下 | `split_long` 迴圈拆到 raw 過門檻 |
| 座標寫死在頁尾底下 | **跟字數無關**，每次都溢出 | 圖說 16.30–17.30 cm、圖庫標籤框 2.75 cm |
| 元件互搶空間 | 表格附註三行擠在 1.3 cm 框裡 | 先算附註高度，再把表格可用高度縮到它上緣 |
| 共用了不該共用的下限 | 標籤被縮到 8.9pt 投影看不清 | 標籤自己定下限 0.76，不吃 `FIT_FLOOR` |

🚨 **`FIT_FLOOR` 會被 `course_slides_weekly` 的階梯調到 0.52**（那是壓張數用的，
給內文的）。任何「非內文」的元件——圖說、圖庫標籤——都不能跟著吃這個值。

🚨 **圖說位置與圖框高度是同一件事。** 只把圖說往上挪、沒縮圖框，
問題會從 12 處變成 106 處「圖壓字」。兩者綁在 `img_box_h(has_cap)` 裡。

### 稽核器本身也會說謊

第一版報了 16 處「壓字」，實測內文底部都還在框內兩公分以上——**全是誤判**。

**Why**：2026-09-08 我先把整部三國壓成四堂交出去，被退：「太快了，戰役的過程與勢力的結盟等都沒有慢慢講，三國至少要講二十回才行」。使用者的參照是侯文詠與蔡康永《歡樂三國志》有聲書——十片 CD 分上下共二十回，他們第 11 回「劉備你非娶不可」正好落在赤壁之後，所以上部十回收在赤壁是對的。判斷「夠不夠慢」的標準：**討董、官渡、赤壁這種大事件各自要獨立成回甚至拆上下，不能一頁帶過**。

**How to apply**：管線與素材都在 `G:\我的雲端硬碟\玄奘\博一上\家教\三國演義（小三）\_製作原始檔\`，加新回不要從頭做——
1. 寫 `slides_lN.js`（純 JS 陣列，20 個 `{html, note}`）
2. 跑 `python build.py lN`：自動沿用第一回的 CSS／`chr()` Q 版人物／OpenMoji 圖示，**只嵌入該回用到的素材**，未用到的不進檔也不出現在「圖片來源」
3. 跑 `node shots.mjs lN` 逐頁截圖 → 拼成總覽圖**親眼看過再交**

三個踩過的坑：維基共享資源**檔名說一套、圖是另一套**（標 crossbow 的其實是鉤狀鐵器），下載後一定要看圖；`.tier .lbl` 原本 2.4em 會把「袁紹」擠成直排（build.py 已自動修）；含中文路徑用 Bash heredoc 傳給 Python 會亂碼，寫檔一律用 Write 工具走 ASCII 路徑。

每回固定體例：末頁「哪些是小說編的、哪些歷史真的有」＋一句預告下一回；講稿提示（`N` 鍵）裡的 `class="ask"` 是給老師的提問點。詳細現況見 [[project_tutoring_roster]] 與那個資料夾的 `家教說明.md`。
