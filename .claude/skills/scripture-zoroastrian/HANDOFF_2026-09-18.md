## 三、已知的坑（每一個都實際踩過）

### 🚨 EXTRA 不可覆蓋詞庫

`avesta_translate.py` 的專名表從詞庫拉，但曾寫成 `table.update(EXTRA)`，
而 `EXTRA` 硬編了 `"Sraosha": "斯勞沙"`，把詞庫已定的**斯魯沙**靜默蓋掉，
污染全站 109 處。**已改成 `setdefault` 並印出衝突清單**——
看到那個警告就去刪 `EXTRA` 裡的那一條，不要反過來改詞庫。

### 🚨 「拉丁嵌字」要往上追專名表，不是清掉重譯

Yt 12 有 25 段「在 Karshvare Arezahi」這種半英半中，症狀是嵌字，
**根因是七大洲不在 `PLACES_WANTED` 白名單裡**。不修白名單，重譯還是一樣。
（七洲定名已補，依元文琪 Yt 10.15。）

### 🚨 稽核只掃 `segments` 會漏掉一半

修 Sraosha 時我的檢查回報「已清乾淨」，grep 卻還抓得到——
**大半在各檔頂層的 `names` 快照欄**，不在 `segments` 裡。
改檔前先確認迴圈掃到哪些欄位。

但反過來也別急著去「修」那一欄（2026-09-18 查過）：各檔頂層的 `names`
來自 `avesta_fetch.py` 的 `spec.names`，是人工整理的**逐篇小詞表**，
與 `names.json` 不是同一份東西（實測 139 檔全部有差：值不同 306 條、
詞庫查無 486 條）。**沒有任何東西吃它**——翻譯用的是全域 `names.json`，
reader 也不顯示（型別 `data/avesta/sources/index.ts:90` 有宣告，無人使用）。
所以它只會污染 grep 的結果，不會污染站上看到的內容。

### 🚨 venv 的 python 會 re-exec 出子程序，別當成兩個實例

`_whisper_venv\Scripts\python.exe` 是 shim，`Get-Process` 會看到父子兩個 PID。
我曾誤判成重複啟動而停掉，**結果把正在跑的也停了**。
看 `ParentProcessId` 判斷；真的有兩個實例時，它們會互相覆蓋 JSON。

### 🚨 驗「有沒有在做事」不能看 CPU

等 API 回應時 CPU 本來就不動（實測 45 秒 +0.0s，記憶體 113MB 正常）。
**要看譯出段數的增量**，不是 CPU 也不是 PID 活著。

### 🚨 引擎回 429/503/504 先驗模型名

整夜 0 段落地，錯誤看起來像配額或服務中斷，實測是模型名：
同一把 key、同一個 endpoint，`nvidia/nemotron-3-super-120b-a12b` 長期 503，
`deepseek-ai/deepseek-v4-flash-0731` 回 200。已改回。

### 🚨 推理模型的 `<think>` 會讓整批被丟掉

`parse_json_reply()` 負責剝：``` 圍欄 → `<think>…</think>` → 未閉合的 `<think>`
→ 取最外層 `{…}`。四個 doctest 涵蓋這四種長相。

## 四、定名規矩（動任何譯名前必讀）

1. **使用者定名是最高原則**，不進計分也不受出處閘約束。
   查到新證據只在 `recommendation_reason` 記一筆備查，**不可拿去翻案**。
2. 祆教譯名以**元文琪《阿維斯塔》**為權威（全文在電子圖書館，274,078 字，
   可直接統計出現次數當證據）。
3. 詞庫 `name_recommended` 是絕對權威；`EXTRA` 只補詞庫沒有的。
4. 🚨 從元文琪那本取任何專名前，**先驗簡轉繁的「里／裡」污染**——
   opencc 會把「法里东」轉成「法**裡**東」。音譯用「里」不用「裡」。

全文見 `.claude/skills/translation-glossary/naming_rules.md`。

## 六、接下來的順序（有先後，別換）

翻譯程序 `process()` 是**整檔讀進記憶體 → 翻完整檔 → 才寫回**，
所以它在跑的時候動同一批 JSON，寫進去的東西會被它寫回時蓋掉。
以下三步都要等它結束（`--all` 是單趟，跑完就自己退出）。

```powershell
# 0. 確認沒有 avesta_translate 在跑（父子兩個 PID 是同一個實例，見坑）
Get-CimInstance Win32_Process -Filter "Name like '%python%'" |
  Where-Object { $_.CommandLine -like '*avesta_translate*' }

# 1. 先代入逐字相同的節（會多出 69 段英譯、48 段中譯，供下一步翻）
.\_whisper_venv\Scripts\python.exe -X utf8 scripts/avesta_xref_en.py          # 先看
.\_whisper_venv\Scripts\python.exe -X utf8 scripts/avesta_xref_en.py --apply

# 2. 再補譯 + 修專名（--refix 清完違例會自動接著翻全部未譯段落）
.\_whisper_venv\Scripts\python.exe -X utf8 scripts/avesta_translate.py --refix

# 3. 最後驗產物，不是驗流程
.\_whisper_venv\Scripts\python.exe -X utf8 scripts/avesta_zh_gate.py
.\_whisper_venv\Scripts\python.exe -X utf8 scripts/avesta_translate.py --audit
```

🚨 **這一趟 `--all` 跑完不等於全部譯完。**閘會退回「疑為摘要而非全譯」
「漢字比例過低」的段落，退回的仍是未譯狀態，要再跑一趟才會補上。
判斷依據是**譯出段數的增量**，不是 PID 還在或 CPU 有沒有動。
