## 🚨 使用者定下的規則

0. **沒有明確授權，不准動他的 Google 日曆。**（2026-09-04 定調）
   `create_event` / `update_event` / `delete_event` **一律先把要寫的每一筆列成清單給他看，
   等他說可以才呼叫**。「幫我記錄進去」「把行事曆放進去」**不是**授權——那只是要我先整理出來。
   讀 PDF、算日期、擬清單都可以自己做；停在寫入那一步。刪除同理。
   > 那天他丟玄奘 115 學年度行事曆 PDF 說「也先記錄進去」，我直接建了 24 筆校曆事件才被叫停。

1. **校方行事曆只收四種日子。**（2026-09-04 定調）**開學日／寒假（暑假）開始／期中考週／期末考週**，
   就這四種。選課、加退選、停修、送繳成績、預警名單、教學評量、註冊、獎學金這些行政截止日
   **一律不要**——他自己會看學校通知，塞進日曆只是雜訊。
   🚨 週次要照校曆數，**別套「第八週期中、第十六週期末」的通則**：玄奘 115-1 是十八週制，
   期中考週落在**第九週**、期末考週落在**第十八週**。

2. **平日每週固定的東西不進日曆。** 每週都有的課與家教不需要提醒，寫進去只是雜訊。
   日曆只收「假日授課」與「非每週的一次性行程」。這些固定項目只存在於課表與 Word 檔。
3. **行事曆要乾淨。** 事件的**說明欄一律留空**，資訊全部塞在標題。
   不要寫章節進度、不要寫「⚠ 與某某相撞」這類提醒——使用者明確要求拿掉過一次。
4. **假日授課是 8 次，不是 9 次。** 單週六／雙週日各排九格，但**第 17、18 週是自學**，
   所以標題寫「第 1 次」到「第 8 次」，最後一格寫「自學」。
   🚨 115-1 的 `PPA001` 是**七次**——12/27 撞行憲紀念日連假，使用者決定**不補課**。
4a. **國定假日：連假照常上課，只有「假期本日」才停課順延。**（2026-09-07 定調）
   9/26、10/24 只是連假中的週六，12/27 只是連假中的週日，**一律照常上課**；
   只有 `PPA066` 的 10/10 是國慶日本日，停課順延至 10/17（雙週六）。
   別看到連假就整批挪課——他要的是只挪那一天。
4b. **每門課十六週，第 17、18 週是自主學習與文本閱讀。**（2026-09-07 定調）
   週三兩門不是排十八週正課；假日班八次（或七次）對應的就是前十六週。
4c. **講義章節是授課參考，不是非講完不可。**「有些兩章一課就好」「有些章節可以取捨」——
   排不下時把末幾章移到自主學習週自讀是正解，不要硬壓進度或把每次上課塞三四章。
5. **改日期前先算星期幾。** 使用者口述的日期常有月份筆誤（10/18 其實是 9/18、10/5 其實是 9/5）。
   算出星期幾才知道那天是不是授課日、會不會撞家教。用 `datetime.date.fromisoformat(d).weekday()`。
6. **「確定沒問題就把撞期的全刪掉」。** 日期修正後原本的衝突註記多半就不成立了，直接清掉，
   不要留著「已解除」之類的痕跡。
7. **行事曆只在 Google 日曆，Word 不印。**（2026-09-04 定調）使用者要的紙本只有那張**彩色**
   週課表——教課藍、修課綠、家教橙，配色跟 artifact 同一組。假日授課與外務查手機就好，
   不要再在 Word 裡多排一頁行事曆。黑白版的表格他不要。
   `SAT`／`SUN`／`OTHER` 仍留在腳本裡當日曆的對照底本，只有 `--calendar` 才會印出來。

## 🚨 Google 日曆連接器的三個坑

### 一、沒有「建立日曆」這個 API

連接器只有事件層工具（`list_calendars` / `create_event` / `update_event` / `delete_event` /
`list_events` / `search_events` / `suggest_time` / `respond_to_event`），**不能建立日曆，也不能改日曆顏色**。

而 Google 的顏色是綁在**日曆**上的，`.ics` 檔裡的 `COLOR` / `X-APPLE-CALENDAR-COLOR` 只有 Apple 行事曆吃，
Google 匯入時直接忽略。所以「一類一個顏色」只有兩條路：

- 使用者自己在網頁版建多個日曆（左側「其他日曆 → + → 建立新日曆」，建完在「⋮」選色），再逐檔匯入 ics
- 或全部寫進同一個日曆，用**事件層** `colorId` 分類 ← **目前採用這條**

事件色 `colorId`：`2` 鼠尾草綠（家教）／`3` 葡萄紫（法會與會議）／`6` 橘子橘（出遊）／
`10` 羅勒葉深綠。授課**不設 colorId**，直接吃日曆本色。

### 二、全天事件會被位移一天 ⚠ 最容易漏掉

`create_event` 帶 `allDay: true` 時，若 `startTime` 給 `2026-09-06T00:00:00+08:00`，
它會換算成 UTC（`2026-09-05T16:00Z`）再取日期，結果存成 **9/5**——整整早一天，而且畫面上看起來很正常。

**補償寫法：全天事件一律給當地時間中午。**

```
startTime: 2026-09-06T12:00:00+08:00
endTime:   2026-09-07T12:00:00+08:00   # 迄日不含當天，單日事件要給隔天
```

跨兩天的（如 10/16–17 出遊）就給 `10-16T12:00` → `10-18T12:00`。
**定時事件不受影響**，只有 `allDay` 會中招。建完務必用 `list_events` 回頭核對日期。

### 三、`list_events` 的參數名是 `startTime` / `endTime`

不是 `timeMin` / `timeMax`（那是 Google 原生 API 的名字）。傳錯會直接報
`Unknown name "timeMax": Cannot find field`。

另外 `update_event` 的說明是「Fields that are not set will not be updated」，
但**傳空字串 `description: ""` 可以清空描述**，實測有效。

## 課程資料要去哪裡查

### 玄奘大學 — 公開開課查詢（不必登入）

入口 `https://tch.hcu.edu.tw/pub/HCUCur.asp`，**整站 Big5 編碼**，
WebFetch 會讀成亂碼，要自己抓下來 `.decode('big5')`。查詢流程兩層：

```python
# 1) 列出某學年期的所有班級（拿 OpClass 代碼）
'https://tch.hcu.edu.tw/pub/GetOpClass.asp?Years=115&Term=1'
#    頁面裡的 LoadCur('115','1','系所全名','00','BJ1A') 就是參數

# 2) 查某班的開課清單；查詢字串必須用 big5 編碼
p = urllib.parse.urlencode({'Years':'115','Term':'1','TeamNo':'00',
                            'DeptName':'宗教與文化學系博士班1年A班','OpClass':'BJ1A'},
                           encoding='big5')
'https://tch.hcu.edu.tw/pub/CurDataList.asp?' + p
```

宗教與文化學系的 `OpClass` 代碼：

| 代碼 | 班別 | 代碼 | 班別 |
|---|---|---|---|
| `BE1A`–`BE4A` | 大學部 1–4 年 A 班 | `BA1A` `BA2A` | 碩士班 |
| `PA1A` `PA2A` | 二年制在職專班 | `JA1A` `JA2A` | 碩專班 |
| `BJ1A` `BJ2A` | 博士班 | | |

`DeptName` 要填全名（`宗教與文化學系博士班1年A班`），代碼與全名的對應從第一層頁面的
`LoadCur(...)` 抓，不要自己拼。

**回傳的「上課時間」是三位數字串**：`102 103 104` = 星期 1、第 02/03/04 節。
第一位是星期，後兩位是節次。使用者要修的課不一定掛在他自己的班上
（例：日文選讀是博一去修碩一的課），查不到就把全系班別掃一遍。

`https://ilearn.hcu.edu.tw/` 是 **Moodle**。開課查詢只給時段與學分，

腳本 `scripts/hcu_ilearn_sync.py`，帳密讀 `.env` 的

  只列 modules 會整份漏掉。

- 站上教材偶有簡體（例如康德〈答覆這個問題：什麼是啟蒙運動？〉何兆武譯本），

  《クロムヱル伝》《リビングストンの生涯》、藤井武《ルーテルの生涯及び事業》。
抓這批日文讀物踩到的三個坑，三個都是「檔案生出來了、頁數正常、但內容是廢的」：

- 🚨 **J-STAGE 會回「200＋一份打不開的 PDF」**：檔案一兩 MB、Content-Type 正常，
  `fitz` 開起來 0 頁（社会学評論 2002、日本の神学 61 那兩篇就是）。`fetch_web`
  現在會先開開看有沒有頁再寫檔，抓不到就報成待辦，不留空殼。
  它也常在下載到一半斷（`IncompleteRead`）或 SSL 握手逾時，那是連線問題不是沒有
  這篇——重試三次仍失敗才算數（赤江那篇 urllib 三次都斷，換 `requests` 就過）。
- 🚨 **青空文庫是 Shift_JIS**，不是 UTF-8。用 `utf-8 + errors="replace"` 硬解不會
  報錯，只會把整本正文變成「葼 ɓ M ҂ɑ」的單位元組亂碼。`decode_html()` 現在照
  網頁宣告的 charset 解，再依序試 utf-8／shift_jis／euc-jp／big5。
- 🚨 **`text_to_pdf` 不能用內建的 `china-s`**：那是簡體中文字型，編不了日文假名，
  寫出來一樣是亂碼。有假名就嵌 MS 明朝、否則細明體，行寬也要從 92 改成 40
  （CJK 全形，照拉丁寬度排會爆版）。

`scripts/japanese_self_study_plan.py` 產出十五週自學計畫與各週讀本，語料取本機
既有的青空文庫與文語訳聖書快取（`output/source-cache/original-readers/japanese-full/`）。
三件寫死在裡面的判斷：

- **讀量按「實質字數」定**，總字數要扣振假名。文語訳每個漢字都注了假名，
  不扣會把讀量高估一倍。N5 起步一週三百字，期末約七百，一次一節或幾段。
- **每篇讀本都要寫出處**（作者／初出／底本／電子文本／網址／文字遣い／
  節錄範圍／著作權狀態），書目照青空文庫圖書卡原樣抄。
- 🚨 **文體分界只能按段落索引人工指定**。《後世への最大遺物》前面依序是
  はしがき（文語）→ 再版序言（文語）→ 改版序（1925，已是口語）→ 講演本體（口語），
  用字數切必定切錯邊，而兩個檔案打開都正常。上下篇則用 `fit()` 回報實際段落
  區間並寫進檔案，疊到與否肉眼可查。

## 常見動作

**加一筆行程** → 判斷是不是每週固定的。是 → 只改課表與 Word；不是 → `create_event`
（全天記得 12:00 補償）＋ 描述留空 ＋ 依類別給 `colorId`，然後 `list_events` 核對日期。

**改日期** → 先算星期幾 → `update_event` → 檢查該日還有沒有別的事 → 順手清掉不再成立的註記。

**改課表** → 改 `semester_schedule_docx.py` 的 `GRID` → 重跑產 Word（再用 Word COM `ExportAsFixedFormat($dst,17)` 出 PDF）→ 改 artifact 的 `EVENTS`

**第 2 行到倒數第 2 行**（掐掉 `<!doctype…><body>` 與 `</body></html>`）。
